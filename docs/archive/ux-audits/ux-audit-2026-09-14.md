# UX Audit Report — 2026-09-14

**Commit:** `d4f0f35` (main) · **Device:** iPhone 16 / iOS 18.2 simulator · **Launch:** `--uitesting --skip-onboarding --seed-mock-data --clear-workout-checkpoint` (onboarding captured with `--uitesting` only)

## Summary
- **Screens audited:** 11 (Home, Assessment Gateway, My Plan, Progress, Profile, Settings sheet, Rehab Plan, Guided Workout [exercise + rest], Achievements, Onboarding step 1, Recovery Insights detail [source-only — needs a live Cloud Function call, no seeded insight])
- **Total issues found:** 74
- P0 Critical: 3 | P1 High: 18 | P2 Medium: 34 | P3 Cosmetic: 19

**Overall rating: 7 / 10.** The light tabs (Home, My Plan, Progress) have a coherent COIL identity — teal accent, Industry-Bold headers, white cards on a soft page — and the guided workout is focused and well-animated. The two systemic problems are (1) **page chrome splits into two apps**: pushed and secondary screens (Rehab Plan, Achievements, Profile/Settings, Onboarding) drop to a fixed-dark gradient with a plain title bar, so the app flips light → dark → light inside a single flow; and (2) **the design system is under-used**: three different "Start Guided Workout" buttons, two segmented controls, two chip styles, hand-rolled cards on every tab, ~90 hardcoded icon fonts, and a `mutedText` token that fails WCAG AA at the sizes it's used for. Three P0 accessibility gaps (unlabeled toggles, a checkbox that announces as "Square", unlabeled height menus) and five functional P1s (PDF share never appears on saved plans, Home ignores the weekly schedule, every plan is "ACTIVE", "30 seconds reps" copy, a dead "Done" button on the Profile tab) should land before any restyle.

Method note: the simulator `inspect` (frame) API was unavailable in this session, so touch-target sizes come from source (`.frame` values), not measured bounds. Contrast ratios below were computed from the `CoilPalette` hex values in `DesignSystem.swift`.

Screenshots: `scratchpad/audit/01-home.jpg … 10b-onboarding-step1-bottom.jpg` (session scratchpad; not committed).

## Notes for the design pass (brainstorm input)

**What already works and should be kept:** the teal-on-ink brand chrome (wordmark nav + dark tab bar), Industry-Bold uppercase section headers with the gradient rule (`CoilDividerHeader`), white cards on the soft green-grey page, the guided-workout bottom bar with set dots and the colour-coded rest ring, the segmented progress header, the celebration/haptic moments.

**Three levers that would change how the app *feels*, in order of impact:**
1. **One chrome.** Every in-tab screen on the light page with the wordmark bar; the dark gradient reserved for onboarding and (optionally) the rest timer. Today the app changes personality every time you push.
2. **One component vocabulary.** `PrimaryButtonStyle` for every primary CTA, `SecondaryButtonStyle` for the rest, `CoilSegmentedControl`, `ChipButton`, `.cardStyle()`. Roughly a third of the visual drift disappears with no new design.
3. **A real Profile tab and a lighter Progress tab.** Profile shows the person (name, conditions, active plan, streak) with settings grouped beneath; Progress leads with the chart and stats, actions in one row, the outcome prompt as a dismissible banner instead of a 4-button card.

**Constraints to carry into frontend-design:** SwiftUI; every colour/spacing/font from `DesignSystem.swift`; Industry-Bold + Inter are the brand faces (frontend-design's "avoid Inter" rule does not apply here — CLAUDE.md wins); iOS HIG; light-first with the existing dark-mode tokens; keep the COIL teal.
